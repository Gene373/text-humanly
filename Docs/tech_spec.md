# Техническое задание: «Текст по-человечески»

## 1. Цель

Создать веб-приложение, которое упрощает сложные научные и учебные тексты для студентов, сохраняя при этом все факты, имена и цифры оригинала. Приложение решает проблему непонимания канцелярита и профессиональной терминологии.

## 2. Аудитория

Студенты вузов, которым необходимо быстро понять содержание учебных и научных текстов (лекции, статьи, учебные материалы).

## 3. Пользовательский сценарий

Один универсальный сценарий:
1. Студент заходит на сайт, авторизуется (вход по email).
2. Выбирает уровень простоты.
3. Вводит текст одним из доступных способов.
4. Нажимает «Упростить».
5. Получает переписанный текст в понятном стиле.

## 4. Структура и экраны

### 4.1. Экран авторизации
- Поле ввода email.
- Кнопка «Войти» (отправляет ссылку/код для входа).

### 4.2. Главный экран
- Блок выбора уровня простоты (выпадающий список или радиокнопки).
- Блок ввода текста (три вкладки: «Вставить текст», «Загрузить файл», «Загрузить фото»).
- Текстовое поле для ручного ввода (максимум 10 000 знаков).
- Кнопка загрузки файла (PDF, DOCX).
- Кнопка загрузки фото (для OCR-распознавания).
- Кнопка «Упростить».
- Блок результата (отображение упрощённого текста).

### 4.3. Экран обработки (лоадер)
- Индикатор прогресса или спиннер с текстом «Обрабатываем текст…».

## 5. Функции

### 5.1. Упрощение текста
- Основная функция: замена сложного стиля (канцелярит, академический язык) на простой и понятный.
- Сохранение смысла, фактов, имён и цифр оригинала.
- Сохранение структуры: заголовки, маркированные списки, формулы.

### 5.2. Выбор уровня простоты
- Два уровня (определяется в зависимости от реализации):
  - «Чуть проще» — упрощает стиль, но сохраняет академический тон.
  - «Как для новичка» — максимально простой язык, минимум терминов.

### 5.3. Способы ввода текста
- Ручная вставка в текстовое поле.
- Импорт файла (PDF, DOCX).
- Распознавание текста с фото (OCR).

### 5.4. Лимит обработок
- Не более 3 попыток обработки в день на одного пользователя.

### 5.5. Фильтрация контента
- Запрещённый контент (неприемлемые запросы) не обрабатывается — пользователь видит сообщение об отказе.

## 6. Данные

### 6.1. Входные данные
- Текст: до 10 000 знаков.
- Форматы файлов: PDF, DOCX.
- Язык: только русский.

### 6.2. Выходные данные
- Переписанный текст в выбранном уровне простоты.
- Без дополнительных элементов (резюме, списки терминов и т.п.).

## 7. Состояния интерфейса

| Состояние | Описание |
|-----------|----------|
| Авторизация | Пользователь не авторизован |
| Главная (пусто) | Пользователь авторизован, текст не введён |
| Главная (текст введён) | Текст введён, результат не получен |
| Обработка | Результат обрабатывается |
| Результат готов | Упрощённый текст отображён |
| Лимит исчерпан | 3 попытки использованы |
| Ошибка контента | Запрещённый контент |

## 8. Ограничения

- Сохранение структуры текста (заголовки, списки, формулы) обязательно.
- Скорость обработки: без жёстких ограничений по времени.
- Конфиденциальность: без особых требований (текст может сохраняться на сервере).
- Лимит: 3 попытки в день.
- Язык: только русский.

## 9. Требования к мобильной версии

Интерфейс должен быть адаптивным:
- На мобильных устройствах поля ввода и результата располагаются друг под другом.
- Загрузка фото с мобильного устройства должна быть удобной (выбор из галереи / съёмка).

## 10. Критерии приёмки

- Результат воспринимается студентами как «понятнее оригинала» — подтверждается тестированием на реальных пользователях.
- Все факты, имена и цифры оригинала сохранены в упрощённой версии.
- Структура текста (заголовки, списки, формулы) не нарушена.
- Вход по email работает корректно.
- Лимит 3 попытки в день соблюдается.
- Загрузка и обработка файлов (PDF, DOCX) и фото работает без ошибок.

## 11. Дизайн

Визуальный дизайн и UI-компоненты определяются в файле `design.md` (отдельный артефакт, который будет создан на этапе дизайна). Текущее ТЗ ориентировано на функциональность.
